A fix release for the reading pane: crafted messages can no longer freeze
it, nor, on macOS and Linux, make it send a request while images are
blocked.

Lull Mail: local-first IMAP desktop client (triage, reply, compose, labels, filing).

## Highlights

- On macOS and Linux, a message crafted to be read back differently by the
  browser could make a background request even with images blocked, since
  0.15.2. Lull Mail now reads back the page it builds before showing it,
  and if anything forbidden comes back the message is shown as text.
- More crafted messages could freeze the reading pane or the assistant's
  reader, two of them new in 0.15.3: an embedded stylesheet full of image
  references, a very long base address, deeply nested tables or blocks, and
  thousands of @import rules. Each now takes well under a second to show.
- A message too complex to render in reasonable time is shown as its plain
  text, with a note saying so.
- For trusted senders and "Load for this email", preload and prefetch links
  are removed however they are written, and the text is shown as sent,
  links flagged as suspicious included.
- The "images blocked" banner now offers pictures it used to miss
  (image-set(), SVG filters, stylesheets written with escapes or in other
  encodings), and no longer appears for references that load nothing.
- The inbox unread count no longer disappears when the folder list loads
  after the messages.

## Install

| Platform | File | Install |
|----------|------|---------|
| Windows 10/11 | `LullMail-Setup-0.15.4.exe` | Double-click |
| macOS 12+ | `LullMail-0.15.4.dmg` | Open, drag to Applications |
| Linux | `LullMail-0.15.4.tar.gz` | Extract and run `LullMail/LullMail` |

- **Windows**: SmartScreen (unsigned installer). *More info* → *Run anyway*.
- **macOS**: Gatekeeper (app not notarized). Right-click the app → *Open*.

## Notes

- Nothing to migrate. Senders you already trusted for images stay trusted.
- Preload links are now removed from every message, image ones included:
  one engine sends some of them whatever the page's policy says.
