A fix release for the reading pane's image blocker: the crafted messages
listed below no longer freeze it, or slip a request past it on macOS and Linux.

Lull Mail: local-first IMAP desktop client (triage, reply, compose, labels, filing).

## Highlights

- On macOS and Linux, a message the browser reads back differently could make
  a request with images blocked, since 0.15.2. Such a message now opens as text.
- Messages built to freeze the image blocker (huge stylesheets, long base
  addresses, deep nesting, mass @import; two since 0.15.3) no longer do.
- Prefetch and preload links are now removed from every message, unusual
  markup included, and trusted senders' inline frames no longer open.
- Loaded messages keep the blank lines of their preformatted text next to a
  flagged link too.
- The "images blocked" banner now finds pictures it missed: image-set(), SVG
  filters, and stylesheets written with escapes or in other encodings.
- The inbox unread count no longer disappears when the folder list loads
  after the messages.

## Install

| Platform | File | Install |
|----------|------|---------|
| Windows 10/11 | `LullMail-Setup-0.15.4.exe` | Double-click |
| macOS 12+ | `LullMail-0.15.4.dmg` | Open, drag to Applications |
| Linux | `LullMail-0.15.4.tar.gz` | Extract and run `LullMail/LullMail` |

- **Windows**: SmartScreen (unsigned installer). *More info* → *Run anyway*.
- **macOS**: Gatekeeper (app not notarized). Right-click the app → *Open*.

## Notes

- Nothing to migrate. Senders you already trusted for images stay trusted.
- Very large or very deeply nested messages may now open as text; "Show as
  sent" in the inbox renders them anyway, images still blocked.
- Known: a message of several megabytes can keep the app busy for seconds,
  and on macOS and Linux one very long word for up to a minute.
- Known on macOS and Linux: two rare references under a remote base address
  raise the "images blocked" banner although they load nothing.
