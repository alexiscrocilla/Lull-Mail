A privacy fix: with images blocked, an open message no longer loads anything
from the internet.

Lull Mail: local-first IMAP desktop client (triage, reply, compose, labels, filing).

## Highlights

- Blocking remote images now blocks every remote resource in the message,
  not only ordinary pictures. Backgrounds set in the message's styles or on
  tables, web fonts, video posters, SVG pictures and a few rarer forms still
  loaded before, and any one of them can tell a sender you opened the
  message.
- The same protection covers the side reader that opens messages cited by
  the assistant.
- "Load for this email" and trusted senders bring back the sender's
  pictures, styles, fonts and media. Embedded frames and objects stay off.
- Newsletters that point to their pictures with relative paths now show the
  "images blocked" banner, so you can load them; before, nothing told you
  they were there.
- A message built to freeze the reading pane with oversized styles opens
  normally.

## Install

| Platform | File | Install |
|----------|------|---------|
| Windows 10/11 | `LullMail-Setup-0.15.2.exe` | Double-click |
| macOS 12+ | `LullMail-0.15.2.dmg` | Open, drag to Applications |
| Linux | `LullMail-0.15.2.tar.gz` | Extract and run `LullMail/LullMail` |

- **Windows**: SmartScreen (unsigned installer). *More info* → *Run anyway*.
- **macOS**: Gatekeeper (app not notarized). Right-click the app → *Open*.

## Notes

- Nothing to migrate. Senders you already trusted for images stay trusted.
- Build and test tooling updates close three Dependabot advisories; none of
  that tooling ships in the app.
