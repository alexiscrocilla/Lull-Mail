# Local LLM backend — installé séparément du `requirements.txt` principal
# parce que le wheel est lourd (~25 MB de binaires natifs) et n'est pas
# nécessaire pour la branche OpenAI par défaut.
#
# Installation :
#     pip install -r requirements-local.txt \
#         --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cpu
#
# Pourquoi pin 0.3.0 et pas plus récent :
#   - PyPI n'a pas de wheel cp313 pour 0.3.5. Le build source échoue
#     (incompatibilité MSVC moderne avec <chrono> dans llama.cpp).
#   - 0.3.23 (latest 2026) a un wheel sur l'index abetlen mais
#     utilise des instructions CPU non supportées par les Intel
#     Core 12-13ème gen (AVX-512 désactivé sur les P-cores). Crash
#     `STATUS_ILLEGAL_INSTRUCTION` au chargement du modèle.
#   - 0.3.0 est la dernière version dont l'index abetlen publie un
#     wheel cp313 explicite + compatible CPU mainstream. Marche en dev
#     ET dans le binaire frozen PyInstaller.
#
# Pour upgrade :
#   1. Lire l'issue tracker upstream pour vérifier que la version cible
#      a un wheel cp313 disponible sur https://abetlen.github.io/llama-cpp-python/whl/cpu/
#   2. Tester sur un i5-13600K (ou équivalent CPU hybride sans AVX-512)
#      via `python scripts/smoke_llama.py data/models/<un-petit>.gguf`.
#   3. Tester aussi sur un Mac Apple Silicon — le pre-tokenizer évolue
#      entre versions et un modèle Phi-4-mini exige llama-cpp >= 0.3.6.
#
# ──────────────────────────────────────────────────────────────────────
# Accélération GPU NVIDIA — différée à v2
# ──────────────────────────────────────────────────────────────────────
#
# Le code (src/llm/server.py, src/llm/local_provider.py) lit
# `cfg.llm.local.gpu_layers` et passe `--n_gpu_layers <N>` au
# subprocess `llama_cpp.server` quand > 0. La logique est donc PRÊTE
# à utiliser le GPU dès qu'une wheel CUDA cp313 sera disponible.
#
# Pourquoi désactivé par défaut en v1 :
#   - L'index abetlen NE publie PAS de wheels cp313+CUDA+win64 (testé
#     2026-05-13 : cu121/cu122/cu123/cu124 — zéro wheel cp313). Les
#     wheels cp312 existent (29 versions) mais le projet est sur 3.13.
#   - Le build source CUDA sur Windows + MSVC moderne échoue avec la
#     même erreur `std::chrono::system_clock` que la version CPU.
#
# Pour un dev / power-user qui veut quand même activer le GPU :
#   - Solution propre : créer un venv Python 3.12 dédié + installer
#         pip install "llama-cpp-python[server]==0.3.4" \
#             --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cu124
#     puis dans config.yaml, section llm.local : `gpu_layers: 999`.
#   - Sur Apple Silicon, Metal est automatiquement actif dès que
#     `gpu_layers > 0` — pas besoin de wheel séparée, llama.cpp détecte
#     Metal à la compilation et l'utilise.
#
# v2 envisagée : (a) attendre que abetlen publie cp313+CUDA, OU
# (b) basculer le projet sur Python 3.12, OU (c) bundler Ollama comme
# binaire externe. Décision reportée — la perf CPU avec Phi-3.5 +
# Qwen 3B reste correcte pour la cible "free + privé" sur 8-16 Go RAM.

llama-cpp-python[server]==0.3.0
